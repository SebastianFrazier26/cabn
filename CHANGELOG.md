# Changelog

## 2026-09-20

- M1: world data contract, converter core, and CLI build/inspect.
  - `@cabn/world-schema`: zod schemas + inferred types for the world bundle (`world.json` manifest, per-cluster chunks, minisearch index, assets file), a `validateManifest` helper, and committed JSON Schema exports (`pnpm -F @cabn/world-schema gen:jsonschema`).
  - `@cabn/converter`: `convert(source, opts)` turns a `DirSource` or `ZipSource` into a validated world bundle — directory walk with ignores/caps, file classification, preview extraction, deterministic seeded-jitter radial layout, cluster/annex splitting, and a minisearch index. Ships a browser-safe `./browser` entry (no `DirSource`) and the M1 annotation extension point (`Annotator` type + error-code-to-species taxonomy) with no implementations yet.
  - `@cabn/cli`: `cabn build <dir|zipfile>` and `cabn inspect <bundleDir>`.
- M1 code review fixes: zip hardening, collision safety, secret exclusion.
  - `ZipSource` now sanitizes entry names (rejects zip-slip: `..`, absolute paths, backslash traversal) and enforces hard caps *during* extraction via fflate's streaming `Unzip` — entry count, per-entry decompressed bytes (oversized entries become metadata-only), and a new whole-archive decompressed-bytes cap (`maxTotalBytes`, default 256MB), rather than decompressing everything up front like the old `unzipSync` call.
  - `@cabn/converter` default ignore list gains secret-pattern files (`.env`, `.env.*`, `*.pem`, `*.key`, `id_rsa*`, `id_ed25519*`, `*credentials*`, `.npmrc`, `.netrc`): still listed as portals (name visible), content never read into a chunk or the search index. `convert({ includeSecrets: true })` / `cabn build --include-secrets` restore the old behavior.
  - Cluster id slug collisions (e.g. a nested `a/b` vs. a literal `a--b` directory, or a real `foo__2` vs. an annex) now get a short content-hash suffix instead of silently overwriting each other; `WorldManifestSchema` gained cross-reference checks (duplicate cluster/portal ids, dangling `clusterId`/path/`portalIds` references) so a corrupted manifest fails validation instead of loading broken.
  - Root's own annex clusters (root directory with >40 files) are re-attached to the radial layout instead of stacking at the origin.
  - `preview.ts` no longer splits an astral character's UTF-16 surrogate pair at the 120-char cut.
  - `convert.ts` builds chunk file maps via `Map`/`Object.fromEntries` instead of bracket-assigning into a plain object, so a file named `__proto__` no longer vanishes into the prototype setter instead of erroring.
  - `WorldMeta` gained `truncated`/`skippedFiles`; `cabn build`/`cabn inspect` print a warning when a world is partial.
  - All `world-schema` objects are now `z.strictObject` (unknown keys fail validation).
  - `minisearch` pinned to an exact version (no `^`) to match the hardcoded `MINISEARCH_VERSION` constant; `cli.ts`'s `parseArgs` calls moved inside their try/catch so a bad flag exits 1 with a message instead of crashing.
- Repo rebooted as a TypeScript pnpm monorepo (M0 scaffold): workspaces for `packages/*`, `apps/*`, `tools/*`; TypeScript strict ESM, Biome, Vitest, Node 22, CI workflow.
- Rust prototype parked on the `rust-prototype` branch and removed from this branch.
- Icons moved to `assets/source/icons/`.
- Asset pipeline (M2): `@cabn/asset-pipeline` extracts a 28-color canonical palette from the five source icons (hand-rolled median-cut, no quantization library), attempts true-pixel sprite recovery (content-bbox crop, nearest-dominant downscale, palette-snap, gradient-tolerant flood-fill background removal), generates three hand-drawn placeholder sprites from a declarative pixel-map format, and writes a static `assets/generated/preview.html` for human review. Generated palette, recovered sprites, placeholders, and preview are committed; `manifest.json` lets future edits lock individual placeholders against regeneration.
- Asset pipeline art-direction pivot (M2 follow-up): the soft-rendered 1024² originals, not the crisp recovered sprites, are now the in-game art. `matte-originals.ts` reuses the same background-classification grid to cut a feathered alpha matte over the untouched original pixels (`assets/generated/originals/<name>.png` at 1024/512/256, plus 512/256 WebP). `soften.ts` is a new hand-rolled style pass (per-cell neighbor-luminance gradient shading, deterministic per-cell jitter and per-pixel grain, bloom bleed around bright cells, feathered silhouette edges) that turns a crisp pixel-map render back into the source art's soft-chunky look; calibrated by placing `soften(cabin_64)` next to the original `cabin.png` in the preview page. Palette gained 4 curated cool colors (steel gray, bone/moonlight white, pale ghost blue, cool shadow blue-gray) appended after the extracted 28, since the source icons have no cool neutrals. Ghost and character_idle placeholders redrawn (curvier wavy-tailed ghost in the new cool tones; Pokémon-BW-style big-head/short-body character); portal_arch kept as-is. `recover-sprites.ts` refactored to share `computeBackgroundGrid` with the new matte script instead of duplicating it.
- Portal redesign, spellsword character, and file-preview composite (M2 follow-up, ghost untouched): `portal_arch` rebuilt as a weathered stone archway (steel/warm-gray/khaki texture, moss accents, a pale-ghost-blue rune inlay) instead of the wood-and-glow look, plus a 6-frame animation of motes swirling in the opening — `computeMotePositions`/`portalArchFrame` in `pixelmaps/portal-arch.ts` are pure, deterministic functions of frame index, not hand-drawn frames. `portal-animation.ts` renders all frames, a crisp and a softened horizontal strip (`portal_arch_strip(_soft).png`), and an animated `portal_arch_anim.gif` via `gifenc` (new, zero-dep, MIT — the one dependency added this round; hand-rolling GIF's LZW encoding wasn't worth it for a preview asset). `character_idle` restyled as a "spellsword" (hood, cloak over light armor, short sword at the hip, two glowing pale-blue accents tying it to the portal) with narrower, torso-separated arms fixing v3's fused-looking arms. New `portal-composite.ts` renders `assets/generated/portal-preview-composite(_soft).png`: the stone arch with a mock parchment file-preview (8 deterministic pseudo-random code lines) glowing at the edges inside the opening — reference only, for the engine to composite file previews into portals later.
- Character redesign and portal recolor (M2 follow-up, composite and ghost both untouched): `portal_arch`'s stone shifted from grey-yellow (khaki/warm-gray) to grey-blue (steel gray 28 + cool-shadow blue-gray 31 only — no new colors needed) since the warm stone read inconsistently against its own blue rune/motes; animation frames, strips, GIF, and the composite all regenerated to inherit it. `character_idle` reworked again: v3's steel-dominant armor read as a spacesuit, so clothing is now a dithered navy cloak (cool-shadow blue-gray / darkest-brown checkerboard weave) over a dithered warm-orange tunic, with leather (not steel) for the shoulder pad, hood trim, and bracer; the pointed hood peak is now a rounded, low-profile hood with an asymmetric slouchy droop on one side; the hip sword is replaced by a held wizard's staff (wood shaft, steel ring, gem). Palette gained 2 curated purples — deep plum (index 32) and bright amethyst (index 33) — for the staff gem, since neither the extracted nor the existing curated colors have any purple. Arm structure (narrow, outline-separated from the torso) is unchanged from v3. No pure logic changed (palette append and pixel-map/color edits only), so no new tests this round; the existing mote/frame determinism tests were re-run and still pass unmodified.
