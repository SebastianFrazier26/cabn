# Changelog

## 2026-09-21

- M3: the first walkable game world — React↔Phaser bridge, world/preload/walkable scenes, and a demo app that converts and walks a real (fake) repo.
  - `@cabn/engine` goes from a dep-free stub to a real Phaser 3.90 + zustand + mitt package. `bridge/store.ts` is a vanilla zustand store (`mode`, `activeClusterId`, `activePortalId`, `activePortalContent`, `loadedChunks`, `playerPos`, `searchOpen`) for state that must survive a re-render; `bridge/events.ts` is a typed mitt bus (`portal:enter`, `portal:approach`, `cluster:enter`, `chunk:loaded`) for one-shot signals — the two are never used for the same fact. `systems/{chunkCache,portalApproach,previewText}.ts` hold the pure logic (LRU eviction, approach-radius transitions, preview-line clamping) kept deliberately out of the Phaser-touching scene files so it stays unit-testable without a canvas.
  - `scenes/{BootScene,PreloadScene,WorldScene}.ts`: fetch + validate `world.json` (`@cabn/world-schema`'s `validateManifest`), preload sprites/anims, then render biome-tinted ground, dashed cluster paths, cabin/cabinet cluster sprites with labels, fanned animated portal arches with a fading parchment preview panel on approach, and an 8-direction WASD/arrow player (arcade physics, camera follow, placeholder walk-bob since no real walk-cycle frames exist yet) with lazy per-cluster chunk loading (LRU capped at 8). Walking into a portal and pressing E/Enter sets `mode: "file"` with the file's content; `FileScene` proper (syntax highlighting, monster overlays) is M4.
  - `react/CabnGame.tsx` owns the `Phaser.Game` lifecycle from a `{ worldUrl }` prop; `react/FileOverlay.tsx` is the M3 placeholder full-file viewer (Esc to leave), bridged to the vanilla store via a small `useSyncExternalStore` hook instead of pulling in zustand's React bindings package.
  - `apps/demo`: a Vite + React app (`CabnGame` full-viewport under a cottagecore header). `sample-project/` is a fake 15-file Python/TS "harvest-log" garden tracker; `scripts/build-world.mjs` (wired to `predev`/`prebuild`, skip-if-built) converts it via `@cabn/cli`'s `runBuild` into `public/worlds/sample/` and syncs `assets/generated/{originals,placeholders}` into `public/assets/` (both gitignored, regenerated on demand).
  - Engine tests: store transitions, LRU eviction, approach-radius math, preview-line clamping (23 tests, no Phaser import in any tested module). Demo tests: the `build-world.mjs` skip-vs-rebuild decision (4 tests); `sample-project/` is excluded from the demo's own vitest run since it's fixture data with a Node-test-runner file of its own, not a package to test.
- World-hierarchy redesign: a cabin now represents a whole *world*, never a place inside one — walking the M3 demo made that conflation obvious once there was more than one project to convert.
  - `@cabn/world-schema`: `WorldMeta` gains optional `themeSeed: number` (fnv1a of `meta.source`, converter-filled — optional so a pre-existing manifest still validates). New `shelf.ts`: `ShelfManifestSchema`/`ShelfWorldEntrySchema` (`{ cabnVersion, meta: {name, generatedAt}, worlds: [{ id, name, worldUrl, themeSeed, fileCount, totalBytes }] }`, duplicate-id cross-check same as the world manifest) and `validateShelf`/`ShelfManifestValidationError`. `shelf.schema.json` added to the committed JSON Schema exports.
  - `@cabn/converter`: `convert()` fills `meta.themeSeed`. Radial layout ring radius halved (900px/depth -> 450px/depth, jitter 120 -> 60 in lockstep) — the old scale made reaching an inner cluster take too long to walk; layout snapshot and radius-band tests updated to match (deliberate, not a regression). New `buildShelf(worlds, opts?)` (pure, validated output) turns `{name, worldUrl, manifest}[]` into a `ShelfManifest`, slugifying names into ids with numeric-suffix dedupe.
  - `@cabn/cli`: `cabn shelf <bundleDir...> [-o outDir]` reads each bundle's `world.json` and writes a `shelf.json` next to it, with each entry's `worldUrl` a path relative to `outDir` (portable regardless of where the shelf ends up served from).
  - `@cabn/engine`: new `ShelfScene` — a hub world (wizard tower centered, one cabin per shelf entry fanned around it, dashed paths, walk + E to enter) that boots into `BootScene` with the chosen world's url and a `returnTo: { shelfUrl }`. `WorldScene`'s root cluster is now an animated bonfire, not a cabin; every other cabinet (and each shelf cabin) is tinted via new `systems/theme.ts` (`themeFromSeed`: mulberry32 seeded from `themeSeed`, hue free, saturation/lightness clamped to a tasteful band — same seed always produces the same tint). Portal file previews now render *inside* the arch opening (parchment backing, `Phaser.GameObjects.Graphics`-built geometry mask cropping it to an eyeballed interior region, distance-based fade) instead of a floating panel above the sprite. New `systems/facing.ts` (`facingFromVelocity`, pure) drives a back-view character texture when moving mostly upward, front otherwise; `render/playerController.ts` factors the walk/bob/facing/movement-key logic that both `WorldScene` and `ShelfScene` now share instead of duplicating it. `CabnGame`'s prop is now `{ worldUrl } | { shelfUrl }`; a `shelfUrl` boots the shelf, a plain `worldUrl` still boots straight into a world with no way back (no shelf to return to). Wizard-tower/bonfire/character-back-view art lives on a parallel art branch and may not exist yet: `PreloadScene` tracks per-asset load failures and the scenes fall back to a tinted cabinet (tower), a tinted static portal-arch frame (bonfire), or the front sprite (back view) so this branch runs green standalone.
  - `apps/demo`: added a second, contrasting `notes-vault/` fixture (8 markdown-only files: daily notes, recipes, project notes) alongside `sample-project/`; `scripts/build-world.mjs` now converts both and writes `public/worlds/shelf.json` via `@cabn/cli`'s `runShelf`. `App.tsx` mounts `<CabnGame shelfUrl="/worlds/shelf.json" />`; header hint updated for the shelf (E to enter a cabin or portal, Esc to leave a world at the bonfire or close a file).
  - New tests: `themeFromSeed` determinism/clamping, `facingFromVelocity`, `resolveRelativeUrl`, `ShelfManifestSchema`/`validateShelf`, `buildShelf`, `cabn shelf` (CLI dispatch + `runShelf` unit tests), plus the updated layout snapshot/radius-band tests (174 tests passing repo-wide after this round).
- World-hierarchy placeholder sprites (M2 follow-up): three new declarative pixel maps for the world's spawn marker, its shelf centerpiece, and the character's other side. `pixelmaps/bonfire.ts` is a stone-ring-and-crossed-logs base (grey-blue stone reused from `portal_arch`) with `computeFlameHeight`/`bonfireFrame` generating the flame per animation frame the same way `portal-arch.ts` generates its motes — a deterministic envelope-plus-two-sine-flicker function of (column, frameIndex, totalFrames), banded through four warm orange/cream palette entries so the top two bands clear `soften()`'s bloom threshold and the flame glows once softened. New `bonfire-animation.ts` (mirrors `portal-animation.ts`, no GIF since none was needed) renders `bonfire_frame{0-3}(.png/@8x.png/_soft.png)` and `bonfire_strip(_soft).png`, and owns its own `manifest.json` entry since it isn't in `gen-placeholders.ts`'s static list. `pixelmaps/wizard-tower.ts` is a 48x80 round stone tower (coursed masonry in the same steel-gray/cool-shadow-blue-gray pair, moss patches, one glowing pale-ghost-blue window, a conical deep-plum roof with a bright-amethyst tip tying it to the spellsword's staff gem) added to `gen-placeholders.ts`'s list like the existing three. `pixelmaps/character-idle-back.ts` reuses `character-idle.ts`'s exact 24x32 silhouette and palette with the face/tunic swapped for continued hood/cloak dither (nothing there is visible from behind) and the staff reduced to just its wood tip and gem glinting above one shoulder ("edge-on," the rest strapped diagonally across the back under the cloak); front-view files untouched. `soften.ts`'s per-name job list and `preview-page.ts` (new "Hierarchy sprites" section: bonfire frames/strip, tower, back view next to front view) both extended to cover the two new `gen-placeholders.ts` entries.

## 2026-09-20

- M1: world data contract, converter core, and CLI build/inspect.
  - `@cabn/world-schema`: zod schemas + inferred types for the world bundle (`world.json` manifest, per-cluster chunks, minisearch index, assets file), a `validateManifest` helper, and committed JSON Schema exports (`pnpm -F @cabn/world-schema gen:jsonschema`).
  - `@cabn/converter`: `convert(source, opts)` turns a `DirSource` or `ZipSource` into a validated world bundle — directory walk with ignores/caps, file classification, preview extraction, deterministic seeded-jitter radial layout, cluster/annex splitting, and a minisearch index. Ships a browser-safe `./browser` entry (no `DirSource`) and the M1 annotation extension point (`Annotator` type + error-code-to-species taxonomy) with no implementations yet.
  - `@cabn/cli`: `cabn build <dir|zipfile>` and `cabn inspect <bundleDir>`.
- M1 code review fixes: zip hardening, collision safety, secret exclusion.
  - `ZipSource` now sanitizes entry names (rejects zip-slip: `..`, absolute paths, backslash traversal) and enforces hard caps *during* extraction via fflate's streaming `Unzip` — entry count, per-entry decompressed bytes (oversized entries become metadata-only), and a new whole-archive decompressed-bytes cap (`maxTotalBytes`, default 256MB), rather than decompressing everything up front like the old `unzipSync` call.
  - `@cabn/converter` default ignore list gains secret-pattern files (`.env`, `.env.*`, `*.pem`, `*.key`, `id_rsa*`, `id_ed25519*`, `*credentials*`, `.npmrc`, `.netrc`): still listed as portals (name visible), content never read into a chunk or the search index. `convert({ includeSecrets: true })` / `cabn build --include-secrets` restore the old behavior.
  - Cluster id slug collisions (e.g. a nested `a/b` vs. a literal `a--b` directory, or a real `foo__2` vs. an annex) now get a short content-hash suffix instead of silently overwriting each other; `WorldManifestSchema` gained cross-reference checks (duplicate cluster/portal ids, dangling `clusterId`/path/`portalIds` references) so a corrupted manifest fails validation instead of loading broken.
  - Root's own annex clusters (root directory with >40 files) are re-attached to the radial layout instead of stacking at the origin.
  - `preview.ts` no longer splits an astral character's UTF-16 surrogate pair at the 120-char cut.
  - `convert.ts` builds chunk file maps via `Map`/`Object.fromEntries` instead of bracket-assigning into a plain object, so a file named `__proto__` no longer vanishes into the prototype setter instead of erroring.
  - `WorldMeta` gained `truncated`/`skippedFiles`; `cabn build`/`cabn inspect` print a warning when a world is partial.
  - All `world-schema` objects are now `z.strictObject` (unknown keys fail validation).
  - `minisearch` pinned to an exact version (no `^`) to match the hardcoded `MINISEARCH_VERSION` constant; `cli.ts`'s `parseArgs` calls moved inside their try/catch so a bad flag exits 1 with a message instead of crashing.
- Repo rebooted as a TypeScript pnpm monorepo (M0 scaffold): workspaces for `packages/*`, `apps/*`, `tools/*`; TypeScript strict ESM, Biome, Vitest, Node 22, CI workflow.
- Rust prototype parked on the `rust-prototype` branch and removed from this branch.
- Icons moved to `assets/source/icons/`.
- Asset pipeline (M2): `@cabn/asset-pipeline` extracts a 28-color canonical palette from the five source icons (hand-rolled median-cut, no quantization library), attempts true-pixel sprite recovery (content-bbox crop, nearest-dominant downscale, palette-snap, gradient-tolerant flood-fill background removal), generates three hand-drawn placeholder sprites from a declarative pixel-map format, and writes a static `assets/generated/preview.html` for human review. Generated palette, recovered sprites, placeholders, and preview are committed; `manifest.json` lets future edits lock individual placeholders against regeneration.
- Asset pipeline art-direction pivot (M2 follow-up): the soft-rendered 1024² originals, not the crisp recovered sprites, are now the in-game art. `matte-originals.ts` reuses the same background-classification grid to cut a feathered alpha matte over the untouched original pixels (`assets/generated/originals/<name>.png` at 1024/512/256, plus 512/256 WebP). `soften.ts` is a new hand-rolled style pass (per-cell neighbor-luminance gradient shading, deterministic per-cell jitter and per-pixel grain, bloom bleed around bright cells, feathered silhouette edges) that turns a crisp pixel-map render back into the source art's soft-chunky look; calibrated by placing `soften(cabin_64)` next to the original `cabin.png` in the preview page. Palette gained 4 curated cool colors (steel gray, bone/moonlight white, pale ghost blue, cool shadow blue-gray) appended after the extracted 28, since the source icons have no cool neutrals. Ghost and character_idle placeholders redrawn (curvier wavy-tailed ghost in the new cool tones; Pokémon-BW-style big-head/short-body character); portal_arch kept as-is. `recover-sprites.ts` refactored to share `computeBackgroundGrid` with the new matte script instead of duplicating it.
- Portal redesign, spellsword character, and file-preview composite (M2 follow-up, ghost untouched): `portal_arch` rebuilt as a weathered stone archway (steel/warm-gray/khaki texture, moss accents, a pale-ghost-blue rune inlay) instead of the wood-and-glow look, plus a 6-frame animation of motes swirling in the opening — `computeMotePositions`/`portalArchFrame` in `pixelmaps/portal-arch.ts` are pure, deterministic functions of frame index, not hand-drawn frames. `portal-animation.ts` renders all frames, a crisp and a softened horizontal strip (`portal_arch_strip(_soft).png`), and an animated `portal_arch_anim.gif` via `gifenc` (new, zero-dep, MIT — the one dependency added this round; hand-rolling GIF's LZW encoding wasn't worth it for a preview asset). `character_idle` restyled as a "spellsword" (hood, cloak over light armor, short sword at the hip, two glowing pale-blue accents tying it to the portal) with narrower, torso-separated arms fixing v3's fused-looking arms. New `portal-composite.ts` renders `assets/generated/portal-preview-composite(_soft).png`: the stone arch with a mock parchment file-preview (8 deterministic pseudo-random code lines) glowing at the edges inside the opening — reference only, for the engine to composite file previews into portals later.
- Character redesign and portal recolor (M2 follow-up, composite and ghost both untouched): `portal_arch`'s stone shifted from grey-yellow (khaki/warm-gray) to grey-blue (steel gray 28 + cool-shadow blue-gray 31 only — no new colors needed) since the warm stone read inconsistently against its own blue rune/motes; animation frames, strips, GIF, and the composite all regenerated to inherit it. `character_idle` reworked again: v3's steel-dominant armor read as a spacesuit, so clothing is now a dithered navy cloak (cool-shadow blue-gray / darkest-brown checkerboard weave) over a dithered warm-orange tunic, with leather (not steel) for the shoulder pad, hood trim, and bracer; the pointed hood peak is now a rounded, low-profile hood with an asymmetric slouchy droop on one side; the hip sword is replaced by a held wizard's staff (wood shaft, steel ring, gem). Palette gained 2 curated purples — deep plum (index 32) and bright amethyst (index 33) — for the staff gem, since neither the extracted nor the existing curated colors have any purple. Arm structure (narrow, outline-separated from the torso) is unchanged from v3. No pure logic changed (palette append and pixel-map/color edits only), so no new tests this round; the existing mote/frame determinism tests were re-run and still pass unmodified.
